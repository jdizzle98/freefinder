## Session notes (2026-08-01)

Several build/runtime bugs were fixed and the login page was redesigned. Details in git log (commits `d78d9e6`..`2645eb4`), key points worth knowing for future work:

- **shadcn/ui is now part of the stack**, introduced solely for the new `/login` page: `components.json`, `lib/utils.ts` (`cn()`), `components/ui/button.tsx`, and deps `@base-ui/react`, `class-variance-authority`, `clsx`, `lucide-react`, `tailwind-merge`, `tw-animate-css`, `shadcn`. Note this project's shadcn style is `"base-nova"` (built on `@base-ui/react`, **not** Radix) — don't assume classic Radix-based shadcn docs/examples apply directly.
- `app/globals.css` now carries both the original minimal Tailwind setup **and** the shadcn oklch design-token set (`:root`/`.dark`/`prefers-color-scheme` blocks, `@theme inline` color/radius mappings). The rest of the app still uses plain Tailwind color utilities (`bg-gray-50` etc.), not the `bg-primary`/`text-foreground`-style tokens — those are only consumed by the new login page/Button component so far.
- `/login` (`app/login/page.tsx`, `components/login-form.tsx`) was rebuilt from a v0.app export but keeps all original behavior: `supabase.auth.signInWithPassword`, loading/error state, redirect to `/`, the "Remember me" checkbox (still non-functional), and the `/forgot-password` link (that page still doesn't exist).
- `/post` (`app/post/page.jsx`) now redirects unauthenticated users to `/login` via `useAuth()` *before* rendering the form — previously it let anyone reach the form and only found out there was no session after already attempting a Storage upload, which surfaced as a confusing `StorageUnknownError`.
- `/register` (`app/register/page.jsx`) now handles Supabase's "obfuscated user" response: signing up with an already-registered, confirmed email returns success with a fake `user.id` (anti-enumeration behavior, see `@supabase/auth-js` JSDoc on `signUp()`), which used to hit `violates foreign key constraint "users_id_fkey"` when inserting into `public.users`. Now detected via `data.user.identities.length === 0` and surfaced as a clear error instead.
- `app/profile/page.jsx` had a parse error (unclosed JSX/return/function) that broke the whole build; fixed.
- **Known unresolved bug, not part of this session's fixes**: `app/layout.jsx` and `app/layout.tsx` both exist and are both committed. `layout.tsx` is the one Next.js actually renders, and it lacks `<Navbar />` (only `layout.jsx` has it) — meaning the site is currently missing its top nav bar everywhere. There were also uncommitted, in-progress edits sitting on `layout.tsx` (adding `AuthProvider`) when this was discovered — check with whoever's mid-edit before resolving the duplication.
- If Supabase auth/storage calls start throwing `TypeError: Failed to fetch` or the network tab shows `503` from `*.supabase.co`, check whether the Supabase project is paused (common on the free tier after inactivity) before assuming it's a code bug — this happened once this session and cost significant debugging time before being traced to the project itself, not the app.
- `app/layout.jsx`/`app/layout.tsx` duplication (above) was resolved: consolidated into a single `app/layout.tsx` with `AuthProvider` + `Navbar`, `app/layout.jsx` deleted. Doing so also surfaced two latent bugs in `components/layout/Navbar.jsx` that had never actually been compiled before (missing `'use client'`, and an import of a `signOut` export that `lib/supabaseClient.js` never had) — both fixed.

## Session notes (2026-08-02): home/map screen redesign

The home screen (`/`) was redesigned into a mobile-first, full-screen map with floating UI, replacing the old hamburger-button + left-drawer filter + separate circular post button:

- **`app/page.jsx`** (rewritten): full-screen `MapContainer` behind two floating, rounded (`rounded-2xl`), white, subtly-shadowed bars — a top search bar and a bottom 4-icon nav bar (Profile → `/profile`, Filter → opens the filter sheet, Plus → `/post`, Message bubble → `/messages`). Green (`green-600`) is the accent color throughout (active filter icon, Plus button, active filter chips). Filter/search state (`searchQuery`, `distance`, `category`, `timeFilter`) is lifted here and passed down to `MapContainer` and the filter panel.
- **`components/layout/Navbar.jsx`**: now hides itself on `/` via `usePathname()` (`if (pathname === '/') return null;`), since the new bottom floating bar replaces its Profile/Post/Messages links for that screen. Every other route still shows the Navbar normally — this is the *only* route-conditional behavior in the app; don't be surprised if `/` looks like it's missing navigation, it's intentional.
- **`components/map/MapContainer.jsx`**: now accepts `searchQuery`/`distance`/`category`/`timeFilter` props and actually filters what's rendered (not just visual) — a `filteredListings` memo does text match (title/description), category match, a `haversineMiles()` distance cutoff from the user's geolocation (skipped if geolocation was denied), and a "time last posted" bucket cutoff (today/week/month). While wiring this in, also fixed a latent bug: the click/hover popup event handlers were previously re-registered inside the same effect that rebuilds map data — harmless when that only ran once per fetch, but would have stacked duplicate popup handlers on every filter/search change. Moved those `.on(...)` registrations to run once at map init instead.
- **`components/filters/FilterSidebar.jsx`** (redesigned): now a bottom-sheet panel (backdrop + rounded-top white sheet sliding up), not a left-side drawer. Controlled entirely by props from `app/page.jsx` (no more internal `useState`). Also fixed the category `<select>` options, which were lowercase (`furniture`, `clothing`, ...) and never actually matched real listing data — listings are inserted with the Title-Case strings from `app/post/page.jsx`'s `categories` array (`Furniture`, `Clothing`, ...), so the old filter's category dropdown was silently non-functional even before this redesign. Added a new "time last posted" control (preset buttons: Any time / Today / This week / This month).
- **`components/fab/PostFAB.jsx` deleted** — its floating "+" button is now the Plus icon in the new bottom nav bar; confirmed unused anywhere else before removing.

## `scripts/seed.js`

A standalone dev-seed script (8 users, 20 listings across all categories, photos, 30 likes, 10 reviews, all around Orlando, FL) — not part of the app. Uses the Supabase **service role key** (`SUPABASE_SERVICE_ROLE_KEY`, add it yourself to `.env.local`, never commit it or prefix it `NEXT_PUBLIC_`) to bypass RLS and to create real `auth.users` rows via the Admin API (`public.users.id` is a real FK to `auth.users.id`, so fake "users" need real auth accounts, not just a `public.users` insert). Run with `node --env-file=.env.local scripts/seed.js`. Not idempotent — re-running fails loudly on duplicate emails rather than double-seeding; only ever point it at a dev/test project.
